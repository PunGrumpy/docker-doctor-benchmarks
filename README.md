# docker-doctor benchmarks

Scores for the [docker-doctor](https://github.com/PunGrumpy/docker-doctor) OSS leaderboard: well-known open-source projects, scanned with a pinned version of [`@docker-doctor/cli`](https://www.npmjs.com/package/@docker-doctor/cli).

- **[`repos.yaml`](repos.yaml)** — the list of scanned repos.
- **[`results/leaderboard.json`](results/leaderboard.json)** — the ranked scores the leaderboard page reads.
- **[`results/latest.json`](results/latest.json)** — the full snapshot of the most recent run, including failures.
- **`results/per-repo/<slug>.json`** — per-repo detail.

Results are regenerated by the [Scan workflow](.github/workflows/scan.yml) (monthly cron + manual dispatch), which opens a PR so every score change is reviewed before the leaderboard picks it up.

## Methodology

Each repo gets a blobless sparse clone of its default branch (Dockerfiles, compose files, and `.dockerignore` only), then one run of `@docker-doctor/cli --json` at the repo root. The CLI discovers Docker files recursively, lints them, and computes a 0–100 score from the findings; the exact CLI version and scan timestamp are recorded in every results file, and each entry records the commit (`commitSha`) that was scanned.

Things to keep in mind before quoting a number:

- These are **static-analysis lint findings, not a vulnerability audit**. A low score means the Docker files leave best practices on the table, not that the project is unsafe to run.
- **All** Docker files in the repo count — including dev/test compose files, which are often intentionally loose.
- Scores are only comparable **within the same CLI version**. Rules change; a re-scan after a CLI bump can move every number.

## Add your project / request a re-scan

Open a PR adding your repo to `repos.yaml` (public GitHub repos with at least one Dockerfile or compose file). To get a fresh score after improving your Docker files, open an issue or PR asking for a re-scan — maintainers trigger the Scan workflow manually.

Run the same check locally:

```sh
bunx @docker-doctor/cli
```
